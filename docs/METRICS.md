# Hearth Metrics Specification

Canonical definitions, data types, and OpenTelemetry GenAI semantic convention mappings for Hearth prompt caching telemetry.

## 1. Core Token Metrics

| Metric Name | Type | Unit | Description | OTel Attribute Mapping |
|---|---|---|---|---|
| `hearth.usage.input_tokens` | Counter | tokens | Total input tokens submitted to provider | `gen_ai.usage.input_tokens` |
| `hearth.usage.read_tokens` | Counter | tokens | Input tokens read from provider cache at discounted price | `gen_ai.usage.cache_read.input_tokens` |
| `hearth.usage.write_tokens` | Counter | tokens | Input tokens written/created in provider cache with write fee | `gen_ai.usage.cache_write.input_tokens` |
| `hearth.usage.uncached_tokens` | Counter | tokens | Input tokens processed without cache hit or write | `hearth.usage.uncached_tokens` |
| `hearth.usage.output_tokens` | Counter | tokens | Tokens generated by the model | `gen_ai.usage.output_tokens` |

## 2. Efficiency & Financial Metrics

| Metric Name | Type | Unit | Description | Invariant Reference |
|---|---|---|---|---|
| `hearth.read_share` | Gauge / Ratio | ratio (0.0 to 1.0) | Ratio of read tokens to total input: `read / (read + write + uncached)` | Section 10.1 benchmark measure |
| `hearth.cost_usd` | Counter | USD (Decimal) | Exact call or session cost computed in Decimal arithmetic | INV-13 |
| `hearth.cost_ratio` | Gauge / Ratio | ratio | Actual cost divided by uncached baseline cost (`actual_cost / uncached_baseline`) | Section 5.3 formula |
| `hearth.ttft_seconds` | Histogram | seconds | Time to first token (measured from request dispatch to first byte/candidate) | NFR-1 |

## 3. Invalidation & Guard Dimensions

| Dimension / Label | Values | Description |
|---|---|---|
| `hearth.session_id` | string | Unique agent execution session identifier |
| `hearth.mode` | `observe`, `safe`, `optimize` | Active Hearth execution mode |
| `hearth.break_cause` | See Break Taxonomy | Invalidation cause classification from prefix guard |
| `hearth.user_caused` | `true`, `false` | Attribution flag: whether break was caused by application prompt mutations |

## 4. Provider Field Normalization (INV-06)

Each provider reports cache usage under different field names. Hearth normalizes them so:
$$\text{total\_input} = \text{read} + \text{write} + \text{uncached}$$

- **Google Gemini:**
  - `prompt_token_count` $\rightarrow$ `total_input`
  - `cached_content_token_count` $\rightarrow$ `read`
  - `write = 0` (implicit caching)
  - `uncached = prompt_token_count - read`
- **Anthropic:**
  - `input_tokens` $\rightarrow$ `total_input`
  - `cache_read_input_tokens` $\rightarrow$ `read`
  - `cache_creation_input_tokens` $\rightarrow$ `write`
  - `uncached = input_tokens - read - write`
- **OpenAI:**
  - `prompt_tokens` $\rightarrow$ `total_input`
  - `prompt_tokens_details.cached_tokens` $\rightarrow$ `read`
  - `cache_write_tokens` $\rightarrow$ `write`
  - `uncached = prompt_tokens - read - write`
